# AMPC (Adaptive Model Predictive Control) - Simulation Framework

This repository contains the simulation framework for comparing Hybrid and Polytopic Robust Adaptive Model Predictive Control (AMPC) algorithms. 

> **Note:** For imports and folder references to work correctly, ensure that this root folder is set as your Current Working Directory (CWD).

## 📁 Repository Structure

### `utils/`
This folder contains all the recurring functions and classes used across the project, including:
* The `MPC` and `MPC_POLY` controller classes.
* Closed-loop simulation wrappers.
* Functions for polytope generation and 3D drawing/plotting.

## 🚀 Core Simulation Scripts

### `main.py` & `main_poly.py`
These scripts simulate the control of the system used in Cannon's example using, respectively, the **Hybrid AMPC** and the **Polytopic AMPC**. 

By default, the shape of the tube cross-section is fixed to be a square whose faces are perpendicular to the canonical axes.

**Configurable Parameters:**
* `x0`: Initial condition.
* `N_sim`: Number of time steps for the closed-loop simulation.
* `T` and `alpha`: Defines the shape of the tube cross-section.
* `Qx` and `Qu`: Weight matrices for the cost function.
* `N`: Control/prediction horizon.
* `w_max`: Bound on the disturbance, defined as $\lVert w \rVert_\infty \le w_{max}$ or $\lVert w \rVert_2 \le w_{max}$.

**Feedback Gain ($K$) Calculation:**
The feedback gain matrix $K$ can be computed using two different approaches:

1.  **LMI Approach** (`utils.compute_K_poly_LMI_lambda` or `utils.compute_K_LMI_lambda`):
    Solves the matrix inequality: $A_{cl}^T P A_{cl} - \lambda^2 P < 0$ (where $A_{cl} = A(\theta) + B(\theta)K \quad \forall \theta \in \Theta$)

3.  **Contraction Approach** (`utils.compute_K_contraction` or `utils.compute_K_poly_contraction`):
    Solves the optimization problem:
    $$\min \lambda$$
    $$\text{s.t. } T(A(\theta) + B(\theta)K)x_j < \lambda \alpha$$
    (for all $\theta$ and for all vertices $x_j$ of the set $\{x: Tx \le \alpha\}$)

## 🔍 System Generation & Statistical Analysis

### `main_find_feasible_system.py`
This script generates random systems of varying dimensions to test the boundaries and robustness of the Polytopic MPC scheme. State and input constraints ($Fx + Gu \le 1$) are omitted, and the origin is selected as the initial condition.

**Workflow per attempt:**
1. Generates a random system based on parameter ranges.
2. Attempts to find a matrix $K$ using the LMI approach.
3. Defines the tube cross-section shape as the smallest hyper-rectangle bounding the ellipsoid ($x^T P x \le 1$).
4. Attempts to solve the MPC problem.
5. Logs the feasibility level (e.g., *Success*, *K impossible to find*, *MPC crashed*, *Infeasible problem*).

**Configurable Parameters:**
* `n_min`, `n_max`: Range of state dimensions.
* `m_min`, `m_max`: Range of input dimensions.
* `delta_norm_relative`: Relative norm of the uncertainty matrices ($A_i, B_i$) with respect to the nominal matrices ($A_0, B_0$).
* `stable_system`: Boolean to force generation of strictly stable or unstable systems.
* `w_inf_max`: Norm bound of the disturbance.
* `Horizon`: Prediction horizon.
* `attempts_per_parameter`: Number of generated systems for each combination of parameters.
* `M_theta`, `mu_theta`: Defines the parameter set as $M_\theta \theta \le \mu_\theta$.
* `Pi_w`, `pi_w`: Defines the disturbance set.

### `main_analyse_search.py`
Used to process and analyze the logged results generated by `main_find_feasible_system.py`.

## 📊 Benchmarking & Comparison

### `main_comparison.py`
Simulates the closed-loop control of a specific system using **both** MPC types to directly compare their performance.

* **Inputs:** Requires a `.pkl` file from the results folder containing a dictionary with `A_list`, `B_list`, `theta_star`, and `lambda_LMI`.
* **Assumptions:** Noise bounds $\lVert w\rVert_\infty < 0.05$ and parameter bounds $\lVert \theta\rVert_\infty \le 1$. Initial condition is randomized.
* **Outputs:** Saves state trajectories, input trajectories, estimated parameter sets, and exact computation times for both controllers.

### `main_feasibility_sets.py`
This script performs a high-resolution, parallelized geometric analysis of the feasible regions (sets of valid initial states $x_0$) for the baseline Polytopic MPC versus the Hybrid MPC under various uncertainty geometries.

**Terminology & Uncertainty Geometries:**
The script compares the baseline polytopic approach against several hybrid configurations by altering how the parameter and disturbance uncertainty bounds are defined. 
* **Matrix P:** Refers to the ellipsoid bounding the system's uncertain parameters ($\theta$).
* **Matrix R:** Refers to the ellipsoid bounding the additive disturbance ($w$).
* **"Same Radii" / "Radius":** The absolute bound on the norm ($\lVert x\rVert_\infty$ for the Polytopic baseline, $\lVert x\rVert_2$ for the Hybrid approach) is identical. Because an ellipsoid and a hyper-rectangle with the same radius have different total volumes, the resulting uncertainty sets differ in size.
* **"Same Volume" / "Vol":** The bounds on the $L_2$ norms are mathematically scaled so that the Hybrid hyper-ellipsoids have the exact same volume as the Polytopic hyper-rectangles.
* **Prediction Horizon:** Typically indicated in the output filenames (e.g., $N = 2, 10$, or $20$).

**The 6 Evaluated Configurations:**
1. **Polytopic Baseline:** The feasibility results of Cannon's original MPC.
2. **Case 1 (Same Radii):** Hybrid MPC where both $P$ and $R$ share the same radius/norm bounds as the baseline.
3. **Case 2 (Radius R, Vol P):** Hybrid MPC with the same disturbance radius as the baseline, but the parameter ellipsoid volume is scaled to match the baseline parameter set volume.
4. **Case 3 (Vol R, Radius P):** Hybrid MPC with the disturbance volume scaled to match the baseline, but the parameter radius is identical to the baseline.
5. **Case 4 (Same Volumes):** Hybrid MPC where the bounds of both $P$ and $R$ are scaled to match the exact volumes of the baseline polytopic sets.
6. **Case 5 (Polytopic K, Scaled R&P):** An ablation study. This configuration uses the scaled $R$ and $P$ matrices, but forces the Hybrid MPC to use the exact stabilizing matrix $K$ (and tube cross-section) calculated for the Polytopic baseline. *(Note: Cases 1-4 calculate a custom* $K$ *optimized specifically to stabilize their respective ellipses).*

**Simulation Workflow:**
1. **Dynamic Bounding Box:** Uses the base Hybrid MPC to automatically discover the absolute geometric limits of the feasible space using an exponential-bisection search algorithm.
2. **LMI Pre-calculation:** Efficiently solves the LMI to find the gain $K$ and tube $T$ only for unique parametric bounding shapes ($P_0$ geometries).
3. **Parallel Grid Evaluation:** Creates a dense grid inside the bounding box and uses `joblib` (via task chunking) to evaluate the feasibility of thousands of initial states across the 6 configurations.
4. **Output:** Generates a side-by-side contour plot mapping the exact feasible regions for direct visual comparison.
